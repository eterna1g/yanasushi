# Панель управления YANASUSHI

Панель: `admin.html`. Каталог уже встроен в HTML и виден без JavaScript. Для надёжной общей корзины между страницами и работы с API используйте HTTP/HTTPS. Браузерные модульные импорты заменены готовыми сборками `app.bundle.js` и `admin.bundle.js`.

## Локальный просмотр

```sh
python3 -m http.server 8000
```

Откройте сайт или `admin.html` на порту 8000. Если API ещё не обновлён, показывается встроенное меню. Редактирование, фото и экспорт доступны; для публикации нужен Worker ниже. Черновик автоматически сохраняется в IndexedDB на этом устройстве и восстанавливается после перезагрузки. Экспорт JSON остаётся резервной копией. Ключ администратора не сохраняется.

## Подключение Cloudflare

1. В Cloudflare Workers & Pages создайте KV namespace для меню.
2. В настройках существующего Worker добавьте KV binding с именем `CATALOG` и выберите созданное хранилище.
3. Добавьте секрет `ADMIN_TOKEN`: случайный ключ длиной от 24 символов. Не храните его в GitHub или HTML. Например, сгенерируйте локально: `openssl rand -hex 32`.
4. Сохраните существующие секреты `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Для `ALLOWED_ORIGIN` используйте `https://eterna1g.github.io` без `/yanasushi/`.
5. Опубликуйте обновлённый Worker вместе с импортируемым `catalog.js`. При работе через Wrangler укажите свой namespace в `wrangler.toml`:

```toml
[[kv_namespaces]]
binding = "CATALOG"
id = "ID_ВАШЕГО_NAMESPACE"
```

Затем выполните `wrangler deploy`. Имя Worker в `wrangler.toml` — `yellow-term-d7c1`, URL сайта — `yellow-term-d7c1.zubashenkoserhii.workers.dev`. Перед деплоем используйте аккаунт Cloudflare, которому принадлежит этот Worker. При изменении URL обновите `ORDER_API_URL` в `site-settings.js`, затем выполните `npm run build`. Адрес также можно изменить в поле подключения панели на время сеанса.

6. Загрузите на GitHub Pages все публичные файлы: `index.html`, `sushi.html`, `sets.html`, `promo.html`, `extras.html`, `contacts.html`, `styles.css`, `app.bundle.js`, `admin.html`, `admin.css`, `admin.bundle.js` и всю папку `assets/`. Не загружайте только `index.html`: страницы используют общие файлы.
7. Откройте `/yanasushi/admin.html`, раскройте «Подключение к сайту», проверьте адрес Worker и введите ключ. Сначала загрузите текущее меню, затем редактируйте.

## Работа с меню

- «Добавить позицию» → категория, название, описание, цена, вес, количество, фото.
- Названия и описания поддерживают RU и UA; пустой UA использует RU.
- Фото: HTTPS-ссылка либо загрузка JPEG/PNG/WebP. Загруженное фото уменьшается до 1200 px и встраивается в каталог, отдельный фотохостинг не нужен.
- «Сохранить позицию в черновик» обновляет черновик. «Опубликовать меню» сохраняет весь каталог в KV для посетителей сайта. До первой публикации Worker возвращает исходное меню.
- KV может распространять изменения до минуты. Не редактируйте меню одновременно в нескольких вкладках: последняя публикация заменяет каталог целиком.
- Экспорт JSON — резервная копия; импорт заменяет черновик, после него нужна публикация.
- Максимум 200 позиций, каталог до 8 МБ. Для больших фотоархивов потребуется отдельное хранилище R2.
- Ключ живёт только в памяти страницы. Защиту проверяет сервер; публичный адрес панели не даёт права менять меню.

## Проверка

```sh
npm ci
npm run build
npm test
npm run test:browser
wrangler deploy --dry-run
```

Публикация на GitHub Pages, создание KV, ввод секретов и реальная отправка заказов в Telegram не выполнялись автоматически. Серверная проверка цен при оформлении заказа остаётся отдельной задачей: текущая интеграция Telegram, как и раньше, принимает сформированный клиентом текст.

## Фотографии и анимации

Анимации входят в `app.bundle.js`, фотографии — в папку `assets/`. Все 17 исходных позиций содержат локальные WebP-фото. Источники и лицензии перечислены в `assets/PHOTO_SOURCES.md`. Фото иллюстративные, некоторые общие для категории.

Старые сохранённые позиции без поля `image` получают фото из исходного каталога по ID. Если в панели убрать фото и опубликовать, пустое поле сохраняется и автоматическая подстановка больше не применяется. Имена, цены и удалённые позиции из сохранённого меню не заменяются исходными.

Плавное появление карточек и отклик корзины учитывают системную настройку уменьшения движения. Скрытого до анимации контента нет: при недоступной анимации позиции остаются видны.


## Отдельные страницы и сборка

- `index.html` — главная, категории и 4 популярных блюда.
- `sushi.html` — 6 роллов и 4 нигири.
- `sets.html` — 3 сета.
- `promo.html` — 5 акционных позиций (дублируют товары, а не отдельные блюда).
- `extras.html` — 4 дополнения.
- `contacts.html` — контакты, доставка и оплата.

Готовые страницы содержат карточки прямо в HTML. Даже если API недоступен или JavaScript не загрузился, исходные позиции остаются видимыми. Без JavaScript корзина не работает. Доступное меню Worker заменяет исходное меню с учётом изменений из админ-панели, включая намеренное удаление всех позиций.

Сборка: `npm ci`, затем `npm run build`. После изменения `catalog.js`, шаблонов в `templates/`, `app.js`, `admin.js`, `locales.js`, `menu-view.js` или `motion.js` повторите сборку и загрузите готовые файлы на хостинг. `npm run build` обновляет HTML, обе JS-сборки и готовый файл `cloudflare-worker.js`; никаких действий с заказами или Cloudflare при этом не выполняется. HTML получает версии CSS/JS для обновления браузерного кеша.

`npm run test:browser` проверяет каталог при недоступном API, отключённом JavaScript и заблокированном JS-файле, переходы между страницами, общую корзину и мобильную версию. Для запуска нужен Chromium (`npx playwright install chromium`), либо уже установленный `/usr/bin/chromium`, либо переменная `PLAYWRIGHT_CHROMIUM_EXECUTABLE` с путём к браузеру. Тест поднимает собственный локальный сервер и не отправляет заказы в Telegram.

## Верхняя панель и слайдер главной

- Контакты редактируются в `site-settings.js`: `CONTACTS.instagram`, `whatsapp`, `telegram` — полные HTTPS-ссылки; `phone` — международный номер; `address` — адрес; `mapUrl` — ссылка на карту. Город можно задать отдельно на RU/UA. После изменений выполните `npm run build` и загрузите обновлённые HTML/JS-файлы.
- Действующие данные пока не предоставлены. До заполнения иконки соцсетей ведут в контакты сайта, ссылка с телефоном — на страницу контактов. Адрес из рекламного примера и чужие номера не использованы. Значения телефона и адреса в существующем содержимом контактов пока остаются образцами.
- Баннеры находятся в `assets/banners/`. Это новые изображения для сайта; надписи нанесены средствами HTML, поэтому остаются чёткими и поддерживают RU/UA.
- Тексты и привязки предложений задаются в `promotions.js`. Цены, старые цены и скидки берутся из каталога; после загрузки Worker обновляются и на баннерах. Удалённые предложения не показываются. Доставка использует порог из `site-settings.js`.
- Автопереключение — раз в 6 секунд. Есть стрелки, точки, клавиши ←/→, свайп и кнопка паузы. Поворот слайдов приостанавливается при наведении, фокусе, уходе блока за экран и скрытии вкладки. При системном уменьшении движения автопереключение отключено, ручное управление доступно.
- Без JavaScript видно первое предложение с рабочей ссылкой в меню; карточки товаров, как и раньше, встроены в HTML.
