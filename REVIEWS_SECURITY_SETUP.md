# Отзывы и защищённые заказы — установка

Изменения находятся в ветке `feature/reviews-secure-orders`. Сначала обновляется Worker, затем публикуется интерфейс из этой ветки. Обычный push в GitHub **не обновляет Cloudflare**. Одного копирования `cloudflare-worker.js` в редактор недостаточно: для новой версии требуется привязка Durable Object `PUBLIC_DATA` и миграция класса `PublicData`.

## Установить сервер и сохранить действующее меню

Нужны Node.js 24 и доступ к аккаунту Cloudflare, которому принадлежит Worker `yellow-term-d7c1`.

1. Получите эту ветку в локальную папку проекта:

   ```sh
   git fetch origin
   git switch feature/reviews-secure-orders
   npm ci
   ```

2. Войдите в Cloudflare через браузер:

   ```sh
   npx --yes wrangler@4.153.0 login
   ```

3. В Cloudflare → **Storage & databases → KV** откройте существующее хранилище, которое привязано к Worker как **CATALOG**. Скопируйте его **Namespace ID** (32 шестнадцатеричных символа). Это идентификатор хранилища, не ADMIN_TOKEN. Не создавайте пустое хранилище вместо действующего.

4. Запустите, подставив этот ID:

   ```sh
   npm run deploy:worker -- ВАШ_NAMESPACE_ID
   npm run check:api
   ```

   Скрипт создаёт локальную конфигурацию в игнорируемой папке `.wrangler/deploy/`, сохраняет привязку существующего CATALOG, добавляет PUBLIC_DATA и его SQLite-миграцию. Секреты ADMIN_TOKEN, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID и существующие обычные переменные сохраняются. В API_TOKEN и ADMIN_TOKEN здесь нет необходимости: авторизация Wrangler выполняется на шаге 2.

5. После успешной проверки объедините pull request с `main`. GitHub Actions повторит тесты и опубликует сайт. Привязка PUBLIC_DATA должна появиться в Settings → Bindings. `/health` должен вернуть `apiVersion: 2` и `publicData: true`, а `/reviews` — JSON со списком отзывов.

Скрипт устанавливает `LEGACY_CHECKOUT_UNTIL` на 30 минут вперёд: это временная совместимость с предыдущим интерфейсом во время публикации. Старые заказы в это время уже пересчитываются сервером, ограничиваются по частоте и защищаются от дублей. Только проверка одноразовой формы для старого протокола временно пропускается. Через 30 минут этот путь автоматически закрывается. Поэтому объедините PR сразу после обновления Worker. Новый интерфейс всегда использует одноразовую проверку. Прямой деплой через `wrangler.toml` требует самостоятельно указать действующий CATALOG и не включает это временное окно.

Для проверки сборки без изменения Cloudflare:

```sh
npm run deploy:worker -- ВАШ_NAMESPACE_ID --dry-run
```

Готовый `cloudflare-worker.js` содержит весь код и оба экспорта: обработчик Worker и класс `PublicData`. Если обновлять код через панель Cloudflare после первичной установки, сохраняйте привязку PUBLIC_DATA. Не удаляйте Durable Object: в нём находятся отзывы, фото и записи обработанных заказов.

## Что добавлено

- Страница `reviews.html`: имя, текст 10–1500 символов, оценка 1–5, одно фото JPEG/PNG/WebP. Фото автоматически уменьшается до 960 px и отправляется размером до 400 КБ в base64. Сервер проверяет сигнатуру, размеры и MIME; SVG и внешние ссылки на фото не принимаются.
- Настоящие отзывы, средняя оценка, RU/UA, страницы по 12 отзывов. Нет выдуманных оценок или отзывов. Имя/текст экранируются при выводе. Фото не включаются в общий JSON списка; они выдаются отдельным маршрутом.
- В админке раздел «Отзывы»: просмотр и удаление отзыва вместе с фото по существующему ADMIN_TOKEN. Форма предупреждает посетителя, что имя, текст и фото публикуются открыто.
- Отзывы и фото сохраняются в Durable Object. Крупные фото разбиваются на части до 60 КБ. Агрегаты и удаления обновляются транзакционно. Каталог и слайды остаются в прежнем KV и не перезаписываются установкой.

## Серверные проверки и антиспам

- Число звёзд — только целое 1–5; имя, телефон, адрес, длина текста, тип фото, ID блюд и количества проверяются сервером.
- Одноразовая случайная проверка формы привязана к IP и типу формы, действует 20 минут и принимается не раньше чем через 2 секунды после выдачи. Время проверяется сервером. Заполненное скрытое поле `website` блокирует отправку.
- Атомарные лимиты: 3 новых заказа за 10 минут, 2 отзыва в час, 30 выдач проверок за 10 минут на IP. При превышении — HTTP 429 и Retry-After. Общий IP, например домашний Wi-Fi, делит эти лимиты. Это ограничение частоты и повторов, не гарантия против распределённых ботов; CAPTCHA не подключена.
- Для хранения ограничений используется хеш IP со случайной серверной солью; IP не публикуется с отзывами. Временные записи проверок, лимитов и подтверждений удаляются по alarm.
- Повтор того же ID возвращает сохранённый результат. Один и тот же отзыв нельзя повторно опубликовать в течение суток. Параллельные отправки сериализуются транзакциями.
- Сервер загружает актуальное меню из CATALOG, считает цены в копейках и доставку из `site-settings.js`. Текст и цены из браузера не считаются достоверными. Telegram получает сообщение, составленное сервером. Старый текст запроса игнорируется даже в период совместимости.
- Несовпадение суммы или удалённое блюдо дают HTTP 409 PRICE_CHANGED, заказ не отправляется. Покупатель явно обновляет корзину и подтверждает новую сумму. KV может распространять изменения меню до минуты — проверка использует версию, доступную Worker в момент запроса.
- При явном отказе Telegram разрешено до 3 попыток одного заказа. При потере ответа о доставке повторная отправка блокируется: Telegram не предоставляет ключ идемпотентности, поэтому автоматически повторять неоднозначный запрос нельзя. Корзина сохраняется, оператору нужно проверить наличие заказа.
- Без привязки CATALOG заказы блокируются, чтобы не использовать устаревшие встроенные цены. Без PUBLIC_DATA приём заказов и отзывов закрыт с HTTP 503. Обхода серверных проверок в новом интерфейсе нет. Перед публикацией Actions проверяет готовность API v2. В существующем репозитории Pages использует режим публикации из ветки, поэтому до установки Worker нельзя объединять PR с main.

## Проверки

```sh
npm run build
npm test
npm run test:browser
npm run export
```

Тесты запускают настоящий workerd/Miniflare, KV и SQLite Durable Object, выполняют HTTP/CORS-запросы из Chromium, проверяют подмену цен, гонки отправок, лимиты, фотографии, отзывы, удаление, восстановление формы и корзины после ошибок. Telegram заменён тестовым транспортом; сообщения в настоящий чат не отправляются.
